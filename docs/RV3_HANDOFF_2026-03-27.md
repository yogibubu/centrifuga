# RV3 Handoff Architecture

## Goal

`RV3` is the target program name for the current CeDiTT + centrifugal backend:

- `RV3` = **Ro-Vibrational Van Vleck**

The intent is not to write another monolithic script. The intent is to expose a
single staged pipeline over the code that already exists:

- geometry and harmonic model construction from `rovib_distortion.py`
- point-group and irrep assignment from `symmetry_metadata.py`
- quartic order-2 route from `distortion_workflow.py`
- sextic/H22 diagnostics from `compare_gaussian_sextic.py`
- Gaussian harmonic/anharmonic readers from `gaussian_vpt_parser.py`
- linear order-4 branch from the existing linear-Aliev machinery

## Requested workflow

The target behavior is the one fixed by the current request.

1. User provides the maximum derivative order and separate files for:
   - geometry: `xyz` or Gaussian `log` or Gaussian `fchk`
   - Hessian: Gaussian `fchk` or future `Der2`
   - cubic derivatives: Gaussian `log` or future `Der3`
   - quartic derivatives: Gaussian `log` or future `Der4`
2. Compute point group and rotational constants.
3. If order `>= 2`:
   - read Hessian
   - diagonalize mass-weighted Hessian
   - obtain normal modes
   - assign normal-mode symmetry
   - compute Coriolis, `dI/dQ`, quartic distortion
   - convert from source representation to user-requested representation
4. If order `>= 3`:
   - read cubic derivatives
   - compute sextic distortion, `H22`, and diagnostics
   - enforce consistency between source mode ordering and the internally built harmonic modes
   - enforce representation consistency
5. If order `== 4`:
   - read quartic derivatives
   - for linear molecules, compute vibrational dependence of quartic distortion constants and optical distortion constants
   - enforce the same mode/representation consistency checks
6. Later:
   - GVPT2 vibrational
   - then ro-vibrational GVPT2

## Input-policy decisions

### Geometry source

Supported now:

- `xyz`
- Gaussian `log`
- Gaussian `fchk`

### Hessian source

Supported now:

- Gaussian `fchk`
- text Cartesian Hessian via explicit `xyz + hessian`

Reserved for next step:

- `Der2`

### Cubic source

Supported now:

- Gaussian `log`

Reserved for next step:

- `Der3`

### Quartic source

Supported now:

- Gaussian `log` loading and mode-order validation

Reserved for next step:

- `Der4`

## Consistency policy

This is the main reason to centralize RV3.

Each stage must check:

- atom ordering consistency between geometry-bearing sources
- mode-order consistency between anharmonic source and internally computed harmonic modes
- representation consistency between source-side tensors and user-requested output representation

The scaffold already implements:

- atom-order checks between geometry and Hessian sources
- harmonic-frequency reorder maps for cubic and quartic Gaussian-log data

## Recommended next steps

1. Keep `RV3.py` as the only orchestrator.
2. Add dedicated `Der2/Der3/Der4` readers as separate modules.
3. Migrate the remaining integrated vibro-rotational CeDiTT summary/report routes under `RV3.py`.
4. Promote stage summaries into a stable report schema.
5. Add GVPT2 only after stage 1–5 inputs and representation policies are stable.
