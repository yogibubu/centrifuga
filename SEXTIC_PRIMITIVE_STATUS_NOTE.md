# Sextic Primitive Status Note

This note records what can currently be said, and what cannot yet be said, for
the sextic side in language parallel to the new `H22` formulation.

## What is already established

The current code now supports the following concrete statements.

### 1. First-level object

On the local harmonic model, the sextic first-level tensor `c1` is modewise
proportional to

```text
mu1_i = d(I^-1)/dQ_i.
```

So the first exposed sextic tensor is already a dressed version of the same
first-level inertia object used on the quartic side.

### 2. Second exposed sextic object

The sextic tensor `c2` is not primitive: it is obtained from an unsummed
mode-pair tensor

```text
c2_pair_{ij,abc},
```

and that object is a Coriolis-coupled linear image of the first-level data.

In other words, the presently exposed sextic “second layer” is still generated
from:

- `mu1`,
- Coriolis couplings `zeta`,
- frequency kernels,
- rotational constants.

### 3. Sextic term split

For the full Cartesian sextic set currently exposed in the code

- `aaa`, `aab`, `aac`, `abb`, `abc`, `acc`, `bbb`, `bbc`, `bcc`, `ccc`,

the formula already separates into:

- a geometry part built from `tau`, `c1`, `c2`, Coriolis, and rotational
  denominators;
- an explicit anharmonic part linear in the cubic force constants.

The code now exposes this grouping through
[compare_gaussian_sextic.py](/Users/vincenzobarone/centrifugal/compare_gaussian_sextic.py)
as `sextic_structural_breakdown_hz(...)`.

So for the full currently exposed sextic tensor one can already say:

```text
Phi^(6) = Phi_geometry(mu1, zeta, rot, omega) + Phi_cubic(phi3).
```

### 4. Quartic tensor inside the sextic geometry sector

The quartic tensor `tau` entering the sextic geometry sector is also generated
from the first-level tensor `c1`, hence from `mu1`.

In fact, with the current normalization,

```text
tau_abcd = -2 sum_i nu_i c1_i,ab c1_i,cd,
```

and this identity is now checked directly in
[test_sextic_tau_mu1_bridge.py](/Users/vincenzobarone/centrifugal/test_sextic_tau_mu1_bridge.py).

So, for the currently exposed sextic geometry sector, both of the main tensorial
ingredients

- `tau`,
- `c2_pair`,

are already generated from the first-level object `mu1` (with Coriolis coupling
appearing in the `c2_pair` branch).

This can now be pushed one step further for the full currently exposed sextic
set:

- the geometry contribution obtained from the model formulas,
- and the geometry contribution rebuilt entirely from `mu1`-generated
  `c1`, `tau`, and `c2`,

agree numerically at roundoff on the local benchmark path.

## What is not yet established

This is still weaker than the quartic `H22` result.

For `H22` we now have a clean primitive formulation:

```text
mu2 = B(mu1) - N,
H22 = H22[B(mu1) - N, B(mu1) - N].
```

For the sextics we do **not** yet have an equally clean theorem saying that the
full sextic structure is generated by:

- a first-level object `mu1`,
- a single intrinsic second-level object analogous to `N`,
- plus explicit anharmonic corrections.

At present, the strongest justified statement is only:

- the currently exposed sextic geometry sector is already generated from `mu1`
  alone or from `mu1` plus Coriolis data;
- explicit cubic anharmonicity enters in a separate visible way;
- the role of a genuinely new intrinsic second-level sextic object is still
  open.

## Working interpretation

So the safe parallel picture is:

- quartic `H22`: primitive pair `(mu1, N)`;
- sextics: first-level geometry from `mu1` plus Coriolis coupling, together
  with explicit cubic anharmonicity, while the existence of an additional
  primitive second-level object remains to be clarified.

That is the correct level of claim supported by the current code.
